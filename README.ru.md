Axottle — панель управления инфраструктурой на базе Remnawave, которую вы размещаете на своём сервере. Подключайте серверы, стройте маршруты трафика, следите за состоянием сервисов и работайте с обращениями клиентов в одном месте.

Панель связывает эксплуатационные задачи в общую картину: какие ноды обслуживают маршрут, где возникает проблема с подключением, какой сценарий восстановления подходит и каких клиентов затронул сбой. От первого сервера до распределённой сети — настройка, ежедневная работа и разбор инцидентов остаются в одном интерфейсе.

## Что умеет Axottle

### Проектировать сети в Flow Studio

Собирайте визуальные схемы из входных точек, нод, маршрутов и транзитных пулов. Импортируйте существующие конфигурации Remnawave, управляйте версиями Flow, проверяйте диагностику и применяйте изменения из панели. HAProxy, WARP и Telegram-прокси включаются в общий процесс настройки сети.

### Управлять нодами на всех этапах

Подключайте готовые серверы по SSH или создавайте их через поддерживаемых провайдеров. Объединяйте ноды в группы, настраивайте домены и TLS, смотрите метрики и логи, управляйте службами и устанавливайте обновления через агентов нод.

### Находить проблемы и настраивать восстановление

Проверки здоровья показывают состояние инфраструктуры. В Flow Guard можно собрать сценарий восстановления, задать условия выполнения и выбрать ручной запуск либо явно разрешённую автоматику. История выполнения показывает результат каждой попытки.

### Работать с поддержкой рядом с инфраструктурой

Получайте сообщения из Telegram в виде тикетов, назначайте операторов, контролируйте приоритеты и SLA, сохраняйте историю переписки в обращении. Команда может отвечать из панели, Telegram-форума или отдельного портала.

### Объединять остальные задачи эксплуатации

| Раздел | Что доступно |
| :--- | :--- |
| **Remnawave** | Подключение панелей, синхронизация, резервные копии, обновления и перенос между серверами. |
| **Сетевые сервисы** | Парки HAProxy, прокси-сервисы, OpenFlux, ресурсы CDN и интеграции с DNS. |
| **Безопасность** | Сигналы злоупотреблений, политики Egress Guard, защита нод, права доступа и журнал аудита. |
| **Подписки** | Клиентские страницы подписок, связанные с Remnawave. |
| **Statuspage** | Публичный статус сервисов, наблюдаемые компоненты, инциденты и плановые работы. |
| **Провайдеры и интеграции** | Аккаунты провайдеров, создание серверов и подключение внешних сервисов. |
| **API и MCP** | Внешние клиенты и автоматизация с ограниченными допусками и поиском по каталогу операций. |

## От первой ноды до ежедневной работы

1. **Подключите инфраструктуру.** Настройте Axottle, подключите Remnawave и добавьте ноды.
2. **Соберите Flow.** Выберите ноды, входные точки и маршрутизацию для своего сервиса.
3. **Проверьте и примените.** Просмотрите конфигурацию, примените её и проверьте результат.
4. **Управляйте из одной панели.** Следите за здоровьем, настраивайте восстановление, отвечайте на обращения и публикуйте статус сервисов.

<summary><strong>Сборка из исходников</strong></summary>

В этом репозитории находятся исходники общей основы Axottle. Прикладные модули поставляются отдельно: сборка одного этого checkout не включает все описанные выше возможности продукта. Разделённая поставка ещё готовится.

Нужны Go версии из `go.mod`, Node.js из `web/admin/.nvmrc`, npm и Python 3.

Перед сборкой Go-бинарника соберите публичный UI. Сгенерированные файлы интерфейса не хранятся в этом репозитории исходников.

```sh
python3 scripts/open-core/build-ui.py
go build -trimpath -buildvcs=false -o axottle ./cmd/axottle-core
go test ./...
```

Для самостоятельного запуска в режиме разработки задайте `AXOTTLE_DB_URL` и постоянный `AXOTTLE_SECRET_KEY`, затем выполните `AXOTTLE_HOST=127.0.0.1 ./axottle serve`. Отдельный бинарник движка можно указать через `AXOTTLE_ENGINE_PATH`, а соединение с уже запущенным движком — через `AXOTTLE_ENGINE_SOCKET`.
